Record once.Replay forever.

Promptape is a tiny open-source proxy for AI developers. It records real OpenAI and Anthropic responses the first time your tests run, then replays them: free, instant, identical every time, and fully offline.

Why

Every test that calls a real model costs money, takes seconds, answers a little differently each run, and fails when the provider has a bad day. Hand-written mocks drift from what the API really returns.

Promptape gives you the real thing, recorded. Your tests keep hitting genuine responses from the real API, but only pay for them once.

Three steps, no code changes

The official SDKs read their base URL from an environment variable, so do LangChain, LlamaIndex, the Vercel AI SDK and most other frameworks. Promptape works in any language, because it's just HTTP.

Start the proxy

One static binary. It listens on localhost and keeps recordings in ./tapes.

$ promptape
◉ promptape  mode=auto
  listening  http://127.0.0.1:4000

Point your SDK at it

Your real key still works and is forwarded only while recording.

export OPENAI_BASE_URL=http://127.0.0.1:4000/v1
export ANTHROPIC_BASE_URL=http://127.0.0.1:4000

Run your tests twice

The first run records. Every run after that is free and instant.

$ pytest   # records
$ pytest   # replays: $0, ms
$ promptape report

What's on the tape

Recording and replaying are two sides of the same cassette. Here's what each one does for you.

promptape v0.1

Side A: record

  1. Streams pass through liveTokens reach your app as they arrive while every event is captured with its timing.
  2. Keys never touch diskAuthorization headers are dropped and key-shaped strings in bodies are redacted, so tapes are safe to commit.
  3. Real errors are keptA deterministic 400 is recorded so you can test error handling. Rate limits and 5xx pass through and are never saved.
  4. Every call is pricedToken usage is turned into dollars per model, so you know what your suite costs live.

Side B: replay

  1. Byte for byteThe SDK parses exactly what the API sent, including every server-sent event.
  2. Offline and keylessReplay mode never touches the network. CI needs no API keys at all.
  3. Sequences stay in orderRecord an agent loop that sends the same request several times and every run gets the responses back in the original order.
  4. Original timing, on requestReplay instantly, or at real speed with --replay-speed 1 to test loading states and timeouts.

Tapes are files you can read

One JSON file per unique request, committed next to your tests. When you change a prompt, the diff in your pull request shows exactly how the model's answer changed.

Four modes, like the keys on a deck

Set one with --mode or PROMPTAPE_MODE. Every response says which one served it in an X-Promptape header.

auto

Default, for local work

Replays what's recorded and records what isn't. You pay for each unique request once.

replay

For CI

Never calls the API. An unrecorded request fails with a message naming the missing tape.

record

After changing prompts or models

Always calls the API and replaces old recordings with fresh ones.

passthrough

For debugging

Forwards everything and saves nothing, while still logging cost per call.

Zero keys in CI. Zero spend.

Record locally, commit tapes/, and replay on every push.

  • No API keys stored in your CI secrets
  • No flaky failures from rate limits or outages
  • No surprise bill from a busy week of pull requests
  • Tests that run in milliseconds instead of minutes
# .github/workflows/test.yml
- name: Start promptape
  run: |
    go install github.com/promptape/promptape/cmd/promptape@latest
    promptape serve --mode replay &
    until curl -sf localhost:4000/_promptape/health; do sleep 0.2; done

- name: Test
  run: pytest
  env:
    OPENAI_BASE_URL: http://127.0.0.1:4000/v1
    ANTHROPIC_BASE_URL: http://127.0.0.1:4000
    OPENAI_API_KEY: replay-only
    ANTHROPIC_API_KEY: replay-only

Where it is, where it's going

Promptape is new. Here is exactly what works today and what comes next.

v0.1

OpenAI and Anthropic APIs, streaming, four modes, secret redaction, cost report, Docker image. Tested end to end with the official Python and TypeScript SDKs.

v0.5

Gemini's native API, failure injection (429, 529, timeouts, cut-off streams), pytest and Vitest plugins, a GitHub Action.

v1.0

Local-model fallback through Ollama, drift detection, a tape browser, a Testcontainers module.

v2.0

MCP server and agent tool-call emulation, so whole agents can be tested without real tools.

Not supported yet: Gemini's native API (its OpenAI-compatible endpoint works today), WebSocket and Realtime APIs, and readable tapes for multipart uploads, which are stored as raw bytes for now. Replays test your code, not the model: run your evals live when you want to measure the model itself.
